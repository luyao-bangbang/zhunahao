# 住哪好 · Where to Stay

> 做攻略的人很多，选酒店的这步，交给 AI 裁决。

**2026 飞猪 AI 旅行创新大赛参赛作品** | 运行平台：阿里云百炼 Managed Agent

## 🎯 一句话说清楚

所有做完旅行攻略的人，最后都卡在同一步：攻略说"住西湖附近"，但"附近"有 300 家酒店民宿，**选哪家？**

```
✈️ 机票已订 → 🗺️ 攻略已做 → 🏨 选哪家酒店？(卡在这) → 🍜 看美食
```

- 机票高铁：价格时刻固定，没得比
- 景区门票：全城同价，同质化
- **住宿：旅行中唯一值得精挑细选的决策**——同价位几百个选择、评价信息庞杂、装修年份/差评/位置通勤维度众多、连住多晚影响全程

「住哪好」不做搬运工，**不列数据，给答案**：用户一句话（"我25号去杭州玩灵隐和西湖，住哪好？"），AI 搜索候选、发起 PK、给出裁决，附飞猪预订链接直接下单。

## ⚔️ 核心功能：酒店 PK 擂台

**8 维度对比**：价格 / 位置通勤 / 装修年份 / 评分+评价条数 / 差评关键词 / 卫生 / 隔音 / 早餐，按用户特征动态加维度（亲子+儿童设施、自驾+停车）。

**AI 裁决（灵魂）**：PK 完必须给结论——

> 裁决：选杭东东 ¥255。差价112元÷2天=56元/天，买到通勤省60分钟+舒适型休息，值。**省钱省错了地方。**

裁决逻辑跟随旅行人格：花得值算性价比、特种兵选便宜的、一天极致看预算段位——**同一个 PK，不同人不同答案**。

**差评关键词解读**：好评都是模板，差评才是真相。AI 提炼"隔音差(23条)、热水不稳(15条)"，帮你读评价而不是翻半小时。评价分析三原则：分数要带条数（4.8分12条 < 4.6分2300条）、差评比好评信息量大、差评要具体到关键词。

## 🧭 决策顺序感知

用户的旅行决策顺序不同，PK 权重跟着变：

| 模式 | 特征 | 裁决逻辑 |
|------|------|---------|
| 行程先定型（主流） | 带着攻略来问"住哪好" | 位置权重拉满，通勤进裁决公式 |
| 酒店先定型 | 度假党/回头客："这家值不值" | 反转：验证酒店 → 反推周边行程 |
| 节点驱动 | 演唱会/漫展："住哪最近" | 场馆半径成硬约束 |

## 🛠️ MCP 原生设计，非爬虫套壳

「住哪好」基于 flyai skill（飞猪 MCP）直连获取结构化数据——酒店价格、装修年份、预订链接，**不模拟人工点击、不解析网页**。

- 数据进出是结构化 JSON，毫秒级响应，无 UI 依赖
- 预订链接回传用户，人只做最后付款确认——合理的人机分工
- 架构天然可扩展：今天接飞猪 MCP，明天日历/地图/支付 MCP 开放，同一个 Agent 无缝扩展跨场景服务

Agent 的正确形态是**以原生方式访问服务**（MCP 直连），而不是"装人"看屏幕找坐标点点点。本作品从第一天就按这个方向设计。

## 🚀 部署步骤（百炼平台）

1. 进入 [阿里云百炼平台](https://bailian.console.aliyun.com/)，选择 **Managed Agent** 创建智能体
2. 在智能体会话中执行：`npx skills add alibaba-flyai/flyai-skill`
3. 前往 [飞猪 FlyAI 开放平台](https://flyai.open.fliggy.com/) 申请 API Key
4. 配置环境变量：`FLYAI_API_KEY=你的Key`
5. 将 `system-prompt.md` 内容设为智能体的系统提示词
6. 测试对话："我25号去杭州，玩灵隐和西湖，住哪好？"
